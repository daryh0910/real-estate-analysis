# Plan: ASIL의 단순함 + TradingView Superchart + 게시판 공유 결합
> 작성일: 2026-05-12
> 프로젝트: real_estate_analysis
> 저장 원칙: Hermes 작업·계획·산출물은 이 프로젝트의 `hermes/` 폴더에 보관한다.

## 1. 목표

- **최종 목표:** 현재 부동산 아파트 분석 앱을 `ASIL 입주물량`처럼 단순하고 빠른 탐색 경험을 제공하면서, TradingView Superchart 수준의 자유 분석과 차트/전략 게시판 공유 기능을 갖춘 투자 분석 플랫폼으로 발전시킨다.
- **성공 기준:**
  1. 사용자가 지역과 기간을 고르면 ASIL처럼 입주/공급 물량을 지도·표·차트로 즉시 확인할 수 있다.
  2. 같은 화면에서 가격, 전세, 거래량, 입주물량, 미분양, PIR, 금리 등 핵심 지표를 TradingView식 Superchart로 겹쳐 볼 수 있다.
  3. 만든 차트 설정과 해석을 게시판에 공유하고, 다른 사용자가 불러와 재현할 수 있다.
  4. 차트 공유가 단순 이미지 공유가 아니라 “데이터 조건 + 지표 + 지역 + 기간 + 해석”까지 저장되는 구조가 된다.

## 2. 현재 확인한 맥락

### 2.1 ASIL 입주물량 페이지에서 확인한 단순 장점

대상 URL:

- `https://asil.kr/asil/sub/movein.jsp`

읽기 점검 결과 페이지 구조:

- 메인 페이지는 iframe 2개로 구성된다.
  - 지도/차트 영역: `/app/household_rts.jsp?os=pc&area=11680`
  - 단지 리스트 영역: `/app/household_rts_list.jsp?...`
- 리스트 데이터는 내부적으로 다음 API성 endpoint를 호출한다.
  - `/app/data/data_movein.jsp?area=11680&order=movein_yyyymm&orderby=desc&sY=2025&sM=1&eY=2027&eM=12`
- 표 컬럼은 매우 단순하다.
  - 위치
  - 단지명
  - 입주년월
  - 총세대수
- 핵심 문구:
  - `APT 입주물량`
  - `출처 : 분양물량조사`
  - 월 단위 업데이트 데이터이며 실시간 모든 입주예정단지를 반영하지 않을 수 있다는 주의 문구가 있다.

ASIL의 핵심 장점은 기능이 많은 것이 아니라 다음이다.

1. **질문이 명확함**
   - “이 지역에 언제 얼마나 입주하나?”
2. **화면이 단순함**
   - 지역 선택, 기간 선택, 지도, 리스트.
3. **공급 판단에 바로 연결됨**
   - 입주년월과 세대수를 바로 보여준다.
4. **상세 단지 리스트가 있음**
   - 집계 숫자만이 아니라 실제 단지명이 나온다.
5. **지도와 표가 붙어 있음**
   - 어디에 몰려 있는지 직관적으로 보인다.

### 2.2 현재 우리 앱의 강점

현재 `real_estate_analysis`는 이미 다음을 보유한다.

- Streamlit 기반 대시보드
- `자유차트 > 슈퍼차트`
- `자유차트 > 전략검증`
- `매물찾기 > 지역검색기`
- 전세-매매 선행 신호
- 조건빌더
- 차트 저장
- 조건 저장
- 관심지역 저장
- SQLite 기반 게시판 인프라
- Plotly figure 등록 함수 `register_fig()`
- 게시글 생성용 `create_post()`
- `saved_charts`, `saved_conditions`, `watchlists` 테이블

현재 약점은 다음이다.

1. ASIL처럼 “한 가지 질문에 바로 답하는 단순 화면”이 부족하다.
2. 공급/입주물량이 차트에는 들어가 있지만, 단지 리스트와 직접 연결되어 있지 않다.
3. Superchart는 존재하지만 TradingView처럼 레이아웃 저장/공유/재현 흐름은 아직 약하다.
4. 게시판 인프라는 있으나, Superchart와 완전히 결합된 “공유 가능한 분석 아이디어” 구조는 미완성이다.

## 3. 제품 방향: “ASIL보다 단순하게 시작하고, TradingView처럼 깊게 들어간다”

## 3.1 핵심 제품 문장

> ASIL처럼 지역별 입주·공급 흐름을 단순하게 보여주고, 관심 지역을 클릭하면 TradingView Superchart처럼 가격·전세·거래·공급·금리를 겹쳐 분석하며, 그 차트와 해석을 게시판에 공유하는 아파트 투자 분석 플랫폼.

## 3.2 화면 철학

1. 첫 화면은 단순해야 한다.
   - 지역
   - 기간
   - 입주물량
   - 가격 흐름
   - 전세 흐름
   - 거래량
   - 후보/주의 신호

2. 깊은 분석은 Superchart로 보낸다.
   - 여러 지역 비교
   - 여러 지표 비교
   - Index=100 비교
   - YoY/MoM
   - 사용자 계산식
   - 정책 이벤트/입주 이벤트 마커

3. 공유는 이미지가 아니라 “분석 세트”여야 한다.
   - 지역
   - 기간
   - 지표
   - 보기 방식
   - 사용자 계산식
   - 차트 이미지
   - 설명
   - 태그
   - 원본 데이터 기준일

## 4. 기능 목표 구조

## 4.1 ASIL형 단순 공급 화면: `입주·공급맵`

### 목표

ASIL의 장점인 “지역별 입주물량을 즉시 이해하는 화면”을 우리 앱에 맞게 구현한다.

### 주요 기능

- 지역 선택
  - 시도
  - 시군구
- 기간 선택
  - 시작 연월
  - 종료 연월
- 입주/공급 물량 집계
  - 월별 입주 세대수
  - 연도별 입주 세대수
  - 누적 입주 세대수
- 지도/표/차트 동시 제공
  - 지도: 시군구별 입주물량 색상
  - 표: 단지명, 위치, 입주년월, 세대수
  - 차트: 월별 입주물량 bar chart
- 비교 지표
  - 입주물량 / 기존 주택수
  - 입주물량 / 가구수
  - 입주물량 / 최근 12개월 거래량
  - 입주물량 / 전세거래량

### ASIL보다 한 단계 나아갈 점

ASIL은 입주물량 자체를 보여주는 데 강하다. 우리는 여기에 다음을 더한다.

1. 가격·전세와 같은 차트에 겹쳐 보기
2. 입주물량이 많은 달 이후 가격/전세 반응 확인
3. 공급 부담 점수화
4. 과거 유사 공급 충격 구간 찾기
5. 관심지역 저장 및 주간 리포트 연결

## 4.2 TradingView Superchart형 `자유차트 2.0`

### 목표

현재 Superchart를 “저장 가능한 분석 캔버스”에서 “공유 가능한 투자 아이디어 차트”로 고도화한다.

### 주요 기능

- 다중 지역
- 다중 지표
- 사용자 계산식
- 보기 방식
  - 원값
  - Index=100
  - YoY
  - MoM
  - 누적 변화율
  - 고점 대비 하락률
  - 저점 대비 반등률
- 보조축 지원
  - 좌측 축: 가격/지수
  - 우측 축: 거래량/입주물량/미분양
- 이벤트 마커
  - 입주 예정 단지
  - 대규모 입주월
  - 정책 이벤트
  - 금리 변곡점
  - 규제지역 이벤트
- 차트 레이아웃 저장
- 차트 공유용 snapshot 생성

### TradingView에서 가져올 핵심 UX

- 저장된 차트 목록
- 지표 조합 프리셋
- 레이아웃 저장
- 링크/게시판 공유
- 다른 사용자의 차트 불러오기
- 차트 설명/아이디어 코멘트

## 4.3 게시판 공유 기능: `투자 아이디어 게시판`

### 목표

차트와 분석 아이디어를 게시판에 저장·공유하고, 다른 사람이 같은 조건으로 차트를 재현할 수 있게 한다.

### 현재 기반

`board.py`에 이미 다음 구조가 있다.

- `posts`
- `comments`
- `likes`
- `saved_charts`
- `saved_conditions`
- `watchlists`

### 추가 목표

게시판 글 하나가 다음을 담아야 한다.

- 제목
- 작성자
- 분석 유형
  - 공급충격
  - 전세선행
  - 저평가
  - 거래량반등
  - 미분양해소
  - 관심지역리뷰
- 지역
- 기간
- 차트 이미지
- 차트 재현 settings JSON
- 사용 지표 목록
- 핵심 코멘트
- 데이터 기준일
- 태그
- 좋아요/댓글

### 게시판 사용 시나리오

1. 사용자가 Superchart에서 `서울 강동구 입주물량 vs 전세가격 vs 매매가격` 차트를 만든다.
2. “게시판에 공유” 버튼을 누른다.
3. 제목과 해석을 입력한다.
4. 차트 이미지와 settings JSON이 함께 저장된다.
5. 다른 사용자는 게시글에서 “이 차트 불러오기”를 누른다.
6. 같은 지역/기간/지표 설정이 Superchart에 복원된다.

## 7. 에이전트 전략

사용자가 agent를 20개까지 허용했다. 이번 주제는 제품 설계와 구현 범위가 넓으므로 멀티 에이전트가 적합하다.

**추천:** 10개 에이전트 병렬 + 1개 통합 PM

| Agent | 역할 | 담당 작업 | 실행 방식 |
|-------|------|----------|----------|
| A | ASIL UX 분석 | 단순 공급맵의 핵심 UX 분해 | 병렬 |
| B | 입주물량 데이터 분석 | 현재 데이터와 공공데이터로 입주/준공/공급 구현 가능성 검토 | 병렬 |
| C | Superchart 설계 | 보조축, 이벤트마커, 레이아웃 저장 설계 | 병렬 |
| D | 게시판 구조 분석 | `board.py` 기준 공유/댓글/좋아요/불러오기 구조 보강안 | 병렬 |
| E | Streamlit UI 설계 | 탭/서브탭/버튼/상태복원 UX 설계 | 병렬 |
| F | Plotly 구현 분석 | 입주물량 bar + 가격 line + 이벤트 marker 구현 패턴 | 병렬 |
| G | 데이터 신뢰도 분석 | 입주/공급 데이터 최신성·출처·주의 문구 설계 | 병렬 |
| H | 테스트 설계 | 저장 settings, 게시글, 차트 복원 테스트 설계 | 병렬 |
| I | 제품전략 | ASIL 단순함과 TradingView 확장성의 균형 설계 | 병렬 |
| J | 리스크 분석 | 데이터 저작권/크롤링/ToS/공유 기능 리스크 | 병렬 |
| PM | 통합 | A~J 결과를 Sprint 실행계획으로 통합 | 순차 |

**질문:** 이 작업을 위 10개 에이전트로 병렬 처리할까요, 아니면 1개 에이전트로 순차 처리할까요?

추천은 10개 병렬이다. 이유는 ASIL UX, 데이터, Superchart, 게시판, 리스크가 서로 독립적으로 분석 가능하기 때문이다.

### 목표

입주물량/공급 이벤트를 가격·전세·거래량과 함께 보는 TradingView형 차트를 만든다.

## 9. 리스크 및 의존성

### 9.1 데이터 리스크

- ASIL 데이터 자체를 무단 수집/복제하는 방식은 피하는 것이 안전하다.
- ASIL은 UX 참고 대상으로 보고, 입주/공급 데이터는 공공데이터 또는 프로젝트 보유 데이터를 우선 사용한다.
- 입주예정 단지 단위 데이터는 출처와 갱신주기를 명확히 표시해야 한다.

### 9.2 기술 리스크

- `app.py`가 이미 4천 줄 이상이라 기능 추가 시 복잡도가 급격히 증가한다.
- 단기 구현은 `app.py`에 추가하되, 중기적으로는 `views/`, `components/` 분리가 필요하다.
- Plotly image export는 `kaleido` 환경 이슈가 있을 수 있다.
- WSL2에서 Linux 브라우저 자동화는 금지한다. 화면 검증은 Streamlit 서버 + Windows 브라우저 수동 확인 방식으로 한다.

### 9.3 제품 리스크

- ASIL식 단순함과 TradingView식 자유도가 충돌할 수 있다.
- 해결책은 화면을 분리하는 것이다.
  - `입주·공급맵`: 단순
  - `슈퍼차트`: 고급
  - `게시판`: 공유/재현

## 10. 검증 기준

- [ ] `입주·공급맵`은 사용자가 10초 안에 해당 지역의 공급 부담을 이해할 수 있다.
- [ ] Superchart는 입주물량, 가격, 전세, 거래량을 한 화면에서 비교할 수 있다.
- [ ] 차트 저장 payload로 동일 차트를 재현할 수 있다.
- [ ] 게시판 글에는 이미지와 settings JSON이 함께 저장된다.
- [ ] 게시글에서 차트를 다시 불러올 수 있다.
- [ ] 데이터 출처와 최신 기준일이 화면에 표시된다.
- [ ] 기존 테스트가 깨지지 않는다.

## 11. 우선 결론

가장 좋은 방향은 다음이다.

1. ASIL을 “데이터 소스”가 아니라 “UX 벤치마크”로 본다.
2. 첫 단계는 `입주·공급맵 v1`이다.
3. 그 다음 `Superchart 2.0`에서 입주/공급 이벤트를 가격·전세·거래량과 겹친다.
4. 마지막으로 `게시판 공유 v1`을 붙여 차트와 투자 아이디어를 공유/재현한다.

즉, 제품 방향은 다음 한 문장으로 정리된다.

> “ASIL처럼 공급을 쉽게 보고, TradingView처럼 자유롭게 분석하고, 게시판처럼 아이디어를 공유하는 아파트 투자 분석 플랫폼.”
