## 3. 가장 큰 갭

## 3.1 ASIL형 핵심 데이터가 부족함

현재 데이터는 가격·전세·거래·공급 proxy가 강하지만, ASIL형 화면의 핵심인 단지 단위 입주예정 데이터가 없음.

필요한 최소 컬럼:

- 위치
- 단지명
- 주소
- 시도
- 시군구
- 지역코드
- 입주예정연월
- 세대수
- 위도/경도 또는 geocoding 가능한 주소
- 출처
- 데이터 기준일

현재 보유 데이터로 가능한 것은 다음 수준임.

- v0: 시도 단위 착공/준공/미분양 기반 공급압력 분석
- v1: 단지명·주소·입주예정월·세대수 기반 ASIL형 입주공급맵

따라서 바로 ASIL과 같은 단지 리스트를 만들기보다, 먼저 “준공/착공 기반 공급압력 v0”로 시작하고 데이터 한계를 명시해야 함.

## 3.2 Superchart는 있으나 재현 가능한 공유 구조가 약함

현재 차트 저장/게시판 기반은 있으나, TradingView처럼 남이 불러와서 같은 차트를 재현하는 contract가 약함.

필요한 저장 payload:

```json
{
  "schema_version": "chart_settings.v1",
  "regions": [],
  "period": {"start": "YYYY-MM", "end": "YYYY-MM"},
  "metrics": [],
  "transform": "raw/index100/yoy/mom",
  "axes": {},
  "filters": {},
  "custom_expr": [],
  "chart_type": "supply_shock/superchart/free",
  "data_metadata_snapshot": {},
  "manifest_run_id": ""
}
```

## 3.3 app.py가 커져서 추가 기능 비용이 증가함

`app.py`가 4천 라인을 넘었고, 다음 책임이 한 파일에 섞여 있음.

- 페이지/탭 구성
- 사이드바 필터
- 데이터 로딩
- 지표 카탈로그
- 조건 빌더
- 차트 생성
- 차트 등록
- 저장/공유 UI
- 게시판 UI

당장 대규모 리팩터링보다, 신규 기능부터 별도 모듈로 만들고 app.py는 조립자 역할로 축소하는 방식이 안전함.

위치:

- 기존 `수요공급분석`의 첫 번째 서브탭으로 배치

- `data/construction_pipeline_sido_monthly.csv`
- `data/unsold_housing_sido_monthly.csv`
- 기존 apt/jeonse/transaction cache

화면 구성:

1. 지역 선택
   - 시도 우선
   - 시군구는 v1에서 강화

2. 기간 선택
   - 최근 36개월
   - 향후 또는 최근 공급 데이터 범위 표시

3. KPI 4개
   - 기간 내 준공/착공 총량
   - 월평균 공급량
   - 최대 공급월
   - 미분양 최신값 또는 공급부담 배지

4. 차트
   - bar: 준공_호수 또는 착공_호수
   - line: 평균가격, 전세_보증금평균
   - 보조축: 거래량, 미분양_호수

5. 주의문구
   - “현재는 단지 단위 입주예정 데이터가 아닌 공식 착공/준공 집계 기반 공급압력 분석입니다.”
   - “단지명·주소·입주예정월 리스트는 v1에서 제공 예정입니다.”

완료 기준:

- 지역과 기간을 선택하면 5초 이내 KPI/차트가 나타남
- 차트가 Superchart로 넘겨질 수 있음
- 출처와 기준일이 화면에 표시됨

## 4.3 데이터 metadata/manifest 도입

현재 부족한 것:

- 지표별 출처
- 기준일
- 수집일시
- 업데이트 주기
- 지역 단위
- 누락률
- 품질등급
- 파생지표 계보
- 다운로드 실행 이력

신규 파일 권장:

- `data/source_metadata.json`
- `data/data_run_manifest.json`

이유:

- 투자판단용 앱은 “숫자가 맞는가”보다 “언제, 어디서 온 숫자인가”가 중요함
- 게시판 공유 시 차트 이미지뿐 아니라 데이터 기준 snapshot이 같이 저장되어야 함

## 4.4 Superchart 저장/복원 contract 고정

우선 구현할 것:

- `chart_settings.v1` schema 정의
- 저장 → 불러오기 → 같은 차트 재현 테스트
- 게시글에 `settings_json`, `data_metadata_snapshot`, `schema_version` 저장
- 게시글 상세에서 `이 차트 불러오기` 버튼 추가

핵심 UX:

- `입주·공급맵`에서 `슈퍼차트로 분석` 버튼 클릭
- 같은 지역/기간/공급지표가 Superchart에 자동 주입
- 사용자가 지표 추가 후 저장
- 게시판에 공유
- 다른 사용자가 같은 설정으로 복원

## 8. 최종 판단

현재 프로젝트는 “데이터 분석 프로토타입”으로는 이미 상당히 강함. 다음 단계는 기능을 더 많이 붙이는 것이 아니라, 첫 질문을 좁히고 저장·공유 contract를 제품 수준으로 고정하는 것임.

가장 좋은 다음 목표는 다음 순서임.

1. ASIL형 `입주·공급맵 v0`를 먼저 만든다.
2. 이 화면의 차트를 Superchart로 넘긴다.
3. Superchart 설정을 schema로 저장한다.
4. 게시판 글을 “차트 아이디어”로 저장한다.
5. 다른 사용자가 그 차트를 그대로 불러올 수 있게 한다.
6. 그 다음 단지 단위 입주예정 데이터를 붙여 ASIL형 v1로 확장한다.

즉, 다음 실행의 핵심은 다음임.

> 지도보다 먼저 `지역/기간/KPI/bar chart/리스트/출처`를 만들고,  
> 예측보다 먼저 `저장/복원/공유 contract`를 고정한다.
