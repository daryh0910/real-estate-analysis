# ASIL 수준의 직관적 이해 1차 목표 실행계획

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 사용자가 앱에 처음 들어와도 10초 안에 “어느 지역에, 언제, 얼마나 공급/매물이 몰리는지”를 ASIL처럼 직관적으로 이해하게 만든다.

**Architecture:** 1차 목표는 기능 확장이 아니라 UX 압축이다. 기존 `app.py`, `data_loader.py`, `buy_decision/`의 계산 로직은 유지하되, 사용자가 처음 보는 화면을 `질문 → KPI → 월별 차트 → 지역/단지 리스트 → 출처` 순서로 재배치한다.

**Tech Stack:** Streamlit, pandas, Plotly, pytest, Streamlit AppTest.

---

## 0. 1차 목표의 정의

ASIL 수준의 직관성은 “많은 지표를 보여주는 것”이 아니라 아래 질문에 즉시 답하는 것이다.

1. 이 지역에 앞으로 얼마나 입주하나?
2. 언제 몰리나?
3. 어느 단지/어느 구가 원인인가?
4. 이 물량이 거래량/전세/미분양 대비 부담인가?
5. 데이터 기준일과 한계는 무엇인가?

따라서 1차 목표는 `입주·공급 이해`를 메인 성공경험으로 만드는 것이다.

### 추가 Goal: 변수 선택형 가설검증 데이터셋·수식환경 확보

입주·공급 빠른보기와 별도로, 사용자가 직접 가설을 세우고 검증할 수 있는 `수식/데이터셋 환경`을 확보한다.

핵심 질문 예시:

1. 선택 지역의 선택 면적대 아파트 매매가는 선택 소득분위의 소득/순자산 대비 얼마나 부담되는가?
2. 시군구 GRDP 증가율과 집값 상승률은 상관관계가 있는가?
3. 국민연금 데이터상 근로자 수 증가율, 1인당 고지금액 증가율과 집값 상승률은 상관관계가 있는가?
4. 같은 서울이라도 강남구/마포구/노원구 등 시군구별 구매력·고용·GRDP와 가격의 관계가 다르게 나타나는가?

필수 변수:

- 지역: 시군구 단위 선택. 예: 서울 전체 시군구, 강남구, 마포구, 특정 지역코드.
- 면적: 전용면적 범위 선택. 예: 82~86㎡를 84 type proxy로 사용하되 사용자가 직접 조정 가능.
- 기간: 시작연도/종료연도 또는 월 범위 선택.
- 가격통계: 평균, 중위, q75, q90 등 선택.
- 소득분위: KOSIS 확보분 기준 `전체`, `소득1분위`~`소득5분위` 선택. 단, 정확한 “상위 10%”는 소득10분위/순자산10분위 원천 추가 확보 필요.
- 설명변수: GRDP, GRDP 증가율, NPS 가입자수, NPS 가입자수 증가율, NPS 1인당고지금액, NPS 1인당고지금액 증가율, 가구소득, 가구순자산 등.

초기 데이터 확보 상태:

- 확보: KOSIS `DT_1HDAAA10` 소득5분위별 자산·부채·소득·순자산, 2017~2024.
- 확보: KOSIS 국세청 시군구별 근로소득, 2016~2023.
- 확보: 국민연금 시군구 월별 가입자수/고지금액.
- 확보: 시군구 GRDP 원천 CSV, 2010~2020 기준.
- 확보: 아파트 실거래 원천 CSV의 지역코드/전용면적/거래금액.
- 미확보/추가탐색: 소득10분위별 소득, 순자산10분위별 순자산. 현재 소득5분위는 상위20% proxy로만 사용한다.

초기 산출 스크립트:

```bash
python hermes/scripts/build_regional_hypothesis_dataset.py \
  --sido 서울 \
  --area-min 82 \
  --area-max 86 \
  --start-year 2017 \
  --end-year 2024 \
  --price-stat median \
  --income-quantile 소득5분위
```

산출물:

- `hermes/output/regional_hypothesis/*regional_hypothesis*.csv`
- `hermes/output/regional_hypothesis/*correlation_summary.csv`

## 1. 성공 기준

### 사용자 성공 기준

- 처음 보는 사용자가 설명 없이도 10초 안에 선택 지역의 공급 부담을 이해한다.
- 필터는 기본 상태에서 `지역`, `기간` 중심으로 단순하다.
- 첫 화면에서 총 입주세대, 월평균, 최대 입주월, 부담 등급이 보인다.
- 월별 bar chart와 단지 리스트가 같은 질문에 답한다.
- 데이터 출처/기준일/주의문구가 화면 하단에 항상 보인다.

### 제품 성공 기준

- `수요공급분석` 탭 안에 ASIL형 `입주·공급 빠른보기` 섹션을 최상단 배치한다.
- 기존 고급 분석은 접거나 아래로 내린다.
- `입주물량`, `인허가/착공/준공`, `미분양`은 세부 분석으로 유지한다.
- 테스트에서 핵심 문구와 컴포넌트 존재를 검증한다.
- Streamlit AppTest 기준 exception_count = 0.

## 2. 화면 구조 v1

### A. 한 문장 질문

상단 문구:

```text
이 지역에 언제 얼마나 입주하나?
```

보조 문구:

```text
지역과 기간만 고르면 총 입주세대, 피크월, 단지 리스트를 바로 확인합니다.
```

### B. 단순 필터

기본 노출:

- 시도
- 시군구
- 기간 프리셋
  - 향후 12개월
  - 향후 24개월
  - 향후 36개월
- 시작 연월
- 종료 연월

고급 필터는 expander로 접는다.

### C. KPI 카드 4개

- 총 입주세대
- 월평균 입주세대
- 최대 입주월 / 세대수
- 공급부담 등급

공급부담 등급 v1:

```text
기간 내 입주세대수 / 최근 12개월 거래량
```

거래량 데이터가 부족하면:

```text
지역 내 입주세대수 분위수 기준
```

등급:

- 낮음
- 보통
- 높음
- 매우높음
- 데이터 부족

### D. 월별 입주물량 차트

- x축: 연월
- y축: 입주예정 세대수
- 최대 월 강조
- 선택 기간 합계 표시
- 피크월 아래에 “이 달의 주요 단지” 리스트 연결

### E. 지역/단지 리스트

기본 컬럼 4개만 먼저 보인다.

- 위치
- 단지명
- 입주년월
- 세대수

부가 정보는 expander 또는 상세보기로 이동한다.

### F. 데이터 출처/주의사항

항상 화면 하단에 표시:

- 출처
- 데이터 기준일
- 업데이트 주기
- 입주 예정 정보는 변경될 수 있음
- 단지 누락 가능성 있음

### Task 1: ASIL형 공급 빠른보기용 순수 함수 추가

**Objective:** UI와 분리된 공급 요약 데이터 모델을 만든다.

- Modify: `data_loader.py` 또는 신규 `buy_decision/supply_view.py`

**Functions:**

```python
def build_supply_quick_view(movein_df, transaction_df=None, region=None, start_ym=None, end_ym=None):
    """ASIL형 빠른 공급 이해 화면에 필요한 KPI, 월별 차트, 단지 리스트, 데이터 품질을 반환한다."""
```

```python
    "monthly_rows": [...],
    "complex_rows": [...],
    "source_notice": [...],
    "data_quality": [...],
```

**Tests:**

- 총 입주세대 계산
- 최대 입주월 계산
- 단지 리스트 4개 컬럼 보존
- 거래량 없을 때도 분위수/데이터 부족으로 graceful fallback

### Task 4: 공급부담 등급을 단순 문장으로 표시

**Objective:** 점수보다 해석을 먼저 보여준다.

**Examples:**

```text
공급부담: 높음
선택 기간 입주예정 물량이 최근 거래량 대비 큰 편입니다. 피크월과 주요 단지를 확인하세요.
```

```text
공급부담: 데이터 부족
거래량 또는 입주예정 데이터가 부족해 정량 등급은 보류합니다.
```

**Tests:**

- 높은 ratio → `높음` 또는 `매우높음`
- 낮은 ratio → `낮음`
- 데이터 부족 → `데이터 부족`
