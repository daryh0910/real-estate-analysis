# ASIL 입주물량 UX 장점의 제품 요구사항 분해

> 작성일: 2026-05-12  
> 프로젝트: real_estate_analysis  
> 목적: ASIL 입주물량 페이지의 “단순하지만 바로 판단 가능한 UX”를 우리 앱의 화면 요건, 사용자 흐름, 우선순위로 변환한다.  
> 확인 방식: 브라우저 자동화 없이 `requests` 읽기 점검. `movein.jsp`와 `data_movein.jsp` 응답 구조 확인.

---

## 1. 확인한 ASIL 구조 요약

대상 페이지: `https://asil.kr/asil/sub/movein.jsp`

확인된 구조:

- `movein.jsp`는 PC용 화면에서 iframe 2개를 사용한다.
  - 지도/차트 영역: `/app/household_rts.jsp?os=pc&area=11680`
  - 리스트 영역: `/app/household_rts_list.jsp`
- 리스트 데이터는 다음 형태로 조회된다.
  - `/app/data/data_movein.jsp?area=11680&order=movein_yyyymm&orderby=desc&sY=2025&sM=1&eY=2027&eM=12`
- 샘플 응답 필드:
  - `name`: 단지명
  - `movein`: 입주년월
  - `household`: 세대수
  - `addr`: 위치
  - 마지막 행에 `sum`: 합계
- 사용자에게 보이는 표 컬럼은 본질적으로 4개다.
  - 위치
  - 단지명
  - 입주년월
  - 총세대수
- 출처와 월 단위 업데이트 주의 문구가 제공된다.

제품 관점 결론:

ASIL의 강점은 데이터나 기능의 복잡함이 아니라 “지역 + 기간 + 단지 + 세대수”만으로 공급 판단 질문에 즉시 답한다는 점이다.

## 2. ASIL UX 장점 8개와 제품 요구사항 변환

| # | ASIL의 단순 장점 | 사용자가 얻는 가치 | 우리 앱 제품 요구사항 |
|---|---|---|---|
| 1 | 질문이 하나다: “어디에 언제 얼마나 입주하나?” | 화면을 배우지 않아도 목적이 즉시 이해됨 | `입주·공급맵` 화면의 첫 문장을 “지역별 입주물량을 한눈에 확인”으로 고정하고, 기본 필터를 지역/기간 2개로 제한 |
| 2 | 필터가 단순하다: 지역 + 기간 | 사용자가 분석 전에 지치지 않음 | 상단 필터는 `시도`, `시군구`, `시작연월`, `종료연월`만 기본 노출. 고급 필터는 접기 처리 |
| 3 | 표 컬럼이 4개뿐이다 | 공급 판단에 필요한 최소 정보만 빠르게 읽음 | 단지 리스트 v1 컬럼은 `위치`, `단지명`, `입주년월`, `세대수`로 시작. 면적, 시공사, 분양가 등은 상세 패널로 이동 |
| 4 | 지도와 리스트가 붙어 있다 | 공급이 어느 동네에 몰리는지 직관적으로 파악 | 좌측 또는 상단에 지도/지역 히트맵, 우측 또는 하단에 단지 리스트를 동기화. 지도 클릭 시 리스트 필터링 |
| 5 | 월별 입주 시점이 바로 보인다 | 특정 월의 전세/매매 압력 가능성을 빠르게 감지 | 월별 입주물량 bar chart를 기본 제공하고, 대규모 입주월을 자동 강조 |
| 6 | 합계가 명확하다 | “이 기간 총 몇 세대인가?”라는 핵심 숫자 확인 | KPI 카드 3개 제공: `총 입주세대`, `월평균 입주세대`, `최대 입주월/세대수` |
| 7 | 출처/업데이트 한계를 표시한다 | 데이터 신뢰도를 사용자가 판단 가능 | 화면 하단에 `출처`, `데이터 기준일`, `업데이트 주기`, `누락 가능성` 문구를 고정 표시 |
| 8 | 상세 분석으로 들어가기 전 탐색이 빠르다 | 공급 과잉/희소 후보 지역을 빠르게 추림 | 각 지역/단지 행에 `슈퍼차트로 분석`, `관심지역 저장`, `게시판 공유 초안` 버튼 제공 |

## 3. 우리 앱의 화면 요건

## 3.1 신규/개편 화면명

추천 화면명: `입주·공급맵`

배치 우선안:

1. 단기: 기존 `수요공급분석` 탭 안의 서브탭으로 추가
2. 중기: 상위 탭으로 독립
3. 고급 분석은 `슈퍼차트`로 연결
4. 공유는 `게시판`으로 연결

---

## 3.2 화면 구성 v1

### A. 상단 검색 영역

필수 요건:

- 시도 선택
- 시군구 선택
- 시작 연월 선택
- 종료 연월 선택
- 조회 버튼
- 기본 기간 프리셋
  - 향후 12개월
  - 향후 24개월
  - 향후 36개월

UX 원칙:

- 첫 화면은 기본값을 자동으로 채워 빈 화면을 피한다.
- 고급 조건은 첫 버전에 넣지 않거나 접는다.

---

### B. 핵심 KPI 카드

필수 요건:

- 총 입주세대
- 월평균 입주세대
- 최대 입주월과 해당 세대수
- 공급부담 간단 등급: 낮음/보통/높음/매우높음

공급부담 등급 v1 산식 예시:

- `기간 내 입주세대수 / 최근 12개월 거래량`
- 또는 데이터가 부족하면 `지역 내 상대 분위수`로 시작

주의:

- 산식이 확정되지 않은 경우 “참고용 점수”로 표시한다.

---

### C. 월별 입주물량 차트

필수 요건:

- 월별 입주세대수 bar chart
- 최대 공급월 강조
- 사용자가 특정 월 클릭 시 해당 월 단지 리스트 필터링
- 향후 Superchart와 동일한 데이터 구조로 넘길 수 있어야 함

확장 요건:

- 매매가격, 전세가격, 거래량, 미분양을 보조축으로 겹쳐 보기
- 대규모 입주월 이후 3/6/12개월 가격 반응 보기

---

### D. 지도 또는 지역 히트맵

v1 현실안:

- 정확한 단지 좌표가 없으면 시군구 단위 choropleth/막대 지도부터 시작
- 단지 좌표 확보 후 marker map으로 확장

필수 요건:

- 지역별 입주물량 색상 표시
- 지역 클릭 시 KPI, 차트, 리스트 동시 갱신
- 지도 없이도 표+차트만으로 화면이 작동해야 함

---

### E. 단지 리스트

필수 컬럼:

- 위치
- 단지명
- 입주년월
- 세대수

필수 기능:

- 입주년월 정렬
- 세대수 정렬
- 단지명 검색
- CSV 다운로드
- 행 클릭 시 상세 패널 표시

상세 패널 v2 후보:

- 주변 가격 흐름
- 주변 전세 흐름
- 동일 행정동 과거 공급
- 해당 단지를 포함한 Superchart 열기

---

### F. 데이터 신뢰도/출처 영역

필수 문구:

- 데이터 출처
- 데이터 기준일
- 업데이트 주기
- 입주 예정 정보는 변동될 수 있음
- 모든 단지를 실시간 반영하지 않을 수 있음

제품 요구사항:

- 출처가 없는 데이터는 공유 게시글에 자동 첨부하지 않는다.
- 게시판 공유 시 `data_as_of`, `source_name`, `source_notice`를 함께 저장한다.

## 4. 사용자 흐름 제안

## Flow 1. ASIL형 빠른 공급 확인

목표: 10초 안에 공급 부담을 이해한다.

1. 사용자가 `입주·공급맵` 진입
2. 기본 지역/기간이 자동 선택됨
3. 총 입주세대, 최대 입주월, 공급부담 등급 확인
4. 월별 bar chart에서 특정 입주 피크월 확인
5. 아래 단지 리스트에서 어떤 단지가 원인인지 확인
6. 필요하면 CSV 다운로드 또는 관심지역 저장

성공 기준:

- 사용자가 스크롤 없이 총량과 피크월을 확인한다.
- 표를 보지 않아도 “많다/적다”의 1차 판단이 가능하다.

---

## Flow 2. 공급 이벤트를 Superchart로 심화 분석

목표: 입주물량이 가격/전세/거래에 미치는 영향을 한 화면에서 본다.

1. 사용자가 `입주·공급맵`에서 지역과 기간 선택
2. `슈퍼차트로 분석` 클릭
3. Superchart에 다음 설정이 자동 전달됨
   - 지역
   - 기간
   - 월별 입주물량
   - 매매가격
   - 전세가격
   - 거래량
4. 사용자는 보조축, Index=100, YoY/MoM, 이벤트 마커를 조정
5. 분석 레이아웃 저장

성공 기준:

- `입주·공급맵`에서 만든 맥락이 Superchart에서 재입력 없이 복원된다.
- 대규모 입주월이 차트 이벤트 마커로 표시된다.

---

## Flow 3. 차트/해석 게시판 공유

목표: 분석 결과를 이미지가 아니라 재현 가능한 아이디어로 공유한다.

1. 사용자가 Superchart에서 분석 완료
2. `게시판에 공유` 클릭
3. 공유 모달에서 제목, 요약, 태그 입력
4. 시스템이 자동 저장
   - 차트 이미지 snapshot
   - chart_settings JSON
   - 지역/기간/지표 목록
   - 데이터 기준일/출처
5. 게시글 생성
6. 다른 사용자가 `이 차트 불러오기` 클릭
7. 동일 설정으로 Superchart 복원

성공 기준:

- 게시글이 단순 캡처가 아니라 재현 가능한 분석 세트가 된다.

---

## Flow 4. 관심지역 반복 모니터링

목표: 사용자가 매주 같은 지역의 공급 변화를 점검한다.

1. 사용자가 `관심지역 저장` 클릭
2. 관심지역 목록에 지역/기간/필터 저장
3. 홈 또는 관심지역 탭에서 공급 피크월, 신규 단지, 데이터 기준일 변경 여부 표시
4. 변경이 있으면 `지난 조회 대비 +N세대` 표시
5. 바로 Superchart 또는 게시판 글 작성으로 연결

성공 기준:

- 분석이 1회성 조회가 아니라 반복 루틴이 된다.

---

## 5. 우선순위 제안

## P0: 반드시 먼저 구현

1. `입주·공급맵 v1` 화면
   - 지역/기간 필터
   - 총 입주세대 KPI
   - 월별 입주물량 bar chart
   - 단지 리스트 4개 컬럼
   - 출처/기준일/주의 문구

2. Superchart 연결 버튼
   - 선택 지역/기간/입주물량을 Superchart 설정으로 전달
   - 최소한 session_state 또는 settings JSON으로 복원 가능해야 함

3. 게시판 공유 payload 정의
   - `chart_settings`
   - `regions`
   - `period`
   - `metrics`
   - `data_as_of`
   - `source_notice`

이유:

- ASIL의 핵심 장점은 P0만으로 재현된다.
- 복잡한 지도/AI 분석 없이도 사용자가 바로 가치를 느낀다.

---

## P1: 사용성을 크게 올리는 기능

1. 지도/지역 히트맵
2. 월별 chart 클릭 → 리스트 필터링
3. 공급부담 점수
4. 대규모 입주월 이벤트 마커
5. 관심지역 저장
6. 게시판 글에서 `이 차트 불러오기`

이유:

- ASIL형 빠른 탐색과 TradingView형 심화 분석이 연결된다.

---

## P2: 차별화/고급 기능

1. 과거 유사 공급충격 구간 찾기
2. 입주 후 3/6/12개월 가격·전세 반응 자동 분석
3. 사용자별 프리셋
4. 댓글에서 차트 변형본 제안
5. 공급/수요/가격 종합 투자 시나리오 템플릿

이유:

- P0/P1의 사용 데이터가 쌓인 뒤 고도화하는 것이 안전하다.

---

## 6. 데이터/저작권/운영 원칙

- ASIL은 UX 벤치마크로만 사용한다.
- ASIL 데이터를 무단 복제하거나 서비스 데이터 소스로 고정하지 않는다.
- 입주/준공/공급 데이터는 공공데이터, 자체 확보 데이터, 라이선스 확인 데이터로 구성한다.
- 모든 화면과 게시글에 데이터 기준일과 출처를 저장한다.
- 입주예정 데이터는 변동 가능성이 크므로 확정 표현을 피한다.

| MI-003 | 사용자는 월별 입주물량을 차트로 볼 수 있다 | P0 | 월 단위 bar chart 표시 |
| MI-004 | 사용자는 단지별 위치/단지명/입주년월/세대수를 표로 볼 수 있다 | P0 | 4개 핵심 컬럼 노출, 정렬 가능 |
| MI-005 | 사용자는 데이터 출처와 기준일을 확인할 수 있다 | P0 | 화면 하단과 공유 payload에 출처/기준일 포함 |
| MI-006 | 사용자는 현재 조회 조건을 Superchart로 보낼 수 있다 | P0 | 클릭 시 지역/기간/입주물량 지표가 Superchart에 복원 |
| MI-007 | 사용자는 월별 차트를 클릭해 해당 월 단지만 볼 수 있다 | P1 | 클릭한 월 기준 리스트 필터링 |
| MI-008 | 사용자는 지도에서 공급 집중 지역을 볼 수 있다 | P1 | 지역별 물량 색상 또는 marker 표시 |
| MI-009 | 사용자는 분석 차트를 게시판에 공유할 수 있다 | P1 | 이미지 + settings JSON + 해석 저장 |
| MI-010 | 사용자는 게시글에서 차트를 다시 불러올 수 있다 | P1 | 저장된 settings JSON으로 Superchart 복원 |

## 8. 최종 권고

1. ASIL의 장점은 “기능이 적다”가 아니라 “판단에 필요한 정보만 남겼다”는 점이다.
2. 우리 앱은 첫 화면을 ASIL처럼 단순하게 만들고, 심화 분석은 Superchart로 분리해야 한다.
3. 게시판 공유는 캡처 이미지가 아니라 재현 가능한 `분석 세트`로 설계해야 한다.
4. 첫 구현은 지도보다 `필터 + KPI + 월별 차트 + 단지 리스트 + 출처 문구`가 우선이다.
5. 성공 기준은 “사용자가 10초 안에 특정 지역의 공급 부담을 이해하고, 1클릭으로 Superchart 심화 분석에 들어가는가”로 잡는다.
