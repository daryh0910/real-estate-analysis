# 부동산 대시보드 배포 데이터 최신화 계획

## 1. 요구 재진술과 가정

- 요구: 운영 중인 Streamlit 부동산 대시보드의 실거래 및 주요 동적 지표를 현재 공개 가능한 최신 데이터로 갱신하고 배포한다.
- 가정 1: 실거래는 실행일(2026-07-20) 기준 전월인 2026-06까지 수집한다.
- 가정 2: 미분양·금리·가격지수·인구이동·KB 지표 등은 원천기관이 실제 제공하는 마지막 시점까지 갱신하며, 공개 지연 자체는 오류로 보지 않는다.
- 가정 3: 정책 이력, 규제 이력, 수작업 입주예정 자료처럼 자동 수집 대상이 아닌 정적 데이터는 이번 범위에서 제외한다.
- 가정 4: 사용자의 사이트 갱신 요청은 검증된 데이터 변경의 Git `main` 반영과 Streamlit Cloud 자동 배포까지 포함한다.

## 2. 작업 분해

1. 갱신 전 기준선 기록
   - 추적 데이터 파일의 행 수, 최신 시점, 크기, 해시와 Git 상태를 `codex/` 보고서에 기록한다.
2. 로컬 스테이징 수집
   - OneDrive 백업 미러에는 쓰지 않는다.
   - 실거래 2026-05~06 원천과 공공·수요 지표를 프로젝트 `codex/260720_배포데이터_최신화_codex/` 아래에 수집한다.
3. 병합 및 캐시 생성
   - 실거래는 기존 Parquet의 대상 월을 교체하는 방식으로 매매 시군구·단지·상세 및 전세·월세·전체임대 캐시를 갱신한다.
   - 공공·수요 지표는 기존 과거 구간을 보존하고 겹치는 최신 구간을 새 수집 결과로 교체한다.
4. 검증
   - 갱신 전후 최신 시점·행 수·중복·필수 컬럼·비정상 값·파일 크기를 비교한다.
   - Python 컴파일, 전체 테스트, 로컬 Streamlit health check를 수행한다.
5. 배포
   - 의도한 데이터 파일과 검증 보고서만 커밋하고 `origin/main`에 푸시한다.
   - Streamlit 공개 URL의 health와 실제 데이터 기준 표시를 재확인한다.

## 3. 리스크와 함정

- 공공 API별 공개 지연과 일시 장애가 다르므로 일부 지표가 2026-06보다 늦을 수 있다. 실패한 원천은 기존 정상 파일을 유지하고 부분 완료로 보고한다.
- 실거래 API는 신고·해제 반영으로 동일 월 데이터가 바뀔 수 있으므로 대상 월은 단순 추가가 아니라 월 단위 교체한다.
- 대용량 Parquet 6종을 동시에 재생성하면 메모리와 디스크 사용량이 커질 수 있어 파일별 순차 생성·검증을 적용한다.
- OneDrive 경로는 읽기만 허용하고 직접 수정하지 않는다.
- `.env`, 토큰, API 키, Streamlit secrets는 출력·커밋하지 않는다.
- Git 푸시는 외부 배포를 유발하는 단계이며, 본 계획 승인 후 실행한다.

## 4. 완료 기준

- [ ] 매매·전세·월세 캐시의 전국 최신월이 2026-06까지 확장되고, 2026-05~06에 유효 거래가 존재한다.
- [ ] 주요 자동 수집 지표가 각 원천의 최신 제공 시점으로 전진하거나, 전진하지 못한 원천은 실패 사유와 기존 파일 유지가 확인된다.
- [ ] 갱신 파일의 필수 컬럼 누락 0건, 핵심 키 중복 0건, 행 수 급감 없음, 가격·면적·거래량 비정상치 0건이다.
- [ ] `py_compile`, 전체 `pytest`, 로컬 Streamlit `/_stcore/health` 검증이 모두 통과한다.
- [ ] Git 변경 범위에 비밀정보와 OneDrive 파일이 없고, `origin/main` 푸시 후 공개 앱 health가 정상이다.

## 5. 검증 방법

- Parquet/CSV별 pandas 요약 스크립트로 `max(연월/연도)`, 행 수, 중복, null, 값 범위를 전후 대조한다.
- 갱신 대상 이름과 이전 임시 경로를 `rg`로 검색해 잔존 참조와 비밀정보 파일 포함 여부를 확인한다.
- `python -m py_compile ...`, `python -m pytest -q`, 로컬 `streamlit run` 및 health endpoint 호출을 수행한다.
- `git diff --stat`, `git diff --check`, 대상 경로 한정 `git status`로 배포 변경을 확인한다.
- 푸시 후 원격 커밋 일치, Streamlit health 및 화면의 최신 기준월을 확인한다.
